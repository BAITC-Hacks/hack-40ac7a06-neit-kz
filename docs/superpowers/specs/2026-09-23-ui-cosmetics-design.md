# Спека: косметика интерфейса

> 23.09.2026. Утверждено по макету (три состояния: подобрали / не проходит никто / как было).
> Затрагивает только слой представления. `lib/`, `data/`, `scripts/`, `tests/` не меняются.

---

## 1. Зачем и в каких рамках

ТЗ кейса про интерфейс говорит прямо: «Красивый UI не входит. Если выбирать между интерфейсом
и качеством объяснений — берите объяснения». Приоритет оценки:
**объяснения > честная обработка редких, занятых и пустых > скорость > интерфейс.**

Отсюда рамка работы: **ни один балл не должен переехать из объяснений в оформление.**
Меняем читаемость и вид, не меняем ни одного слова, которое приходит с бэка,
и не убираем с экрана ничего, что требует ТЗ.

Работа идёт параллельно с правками в `lib/match.ts`, `lib/scoring.ts`, `lib/types.ts`
и слое эмбеддингов. Пересечений нет: всё, что ниже, живёт в `app/` и `public/`.
`lib/types.ts` читается как контракт, изменению не подлежит.

## 2. Что обязано остаться на экране

Проверочный список, по которому сверяется результат. Каждый пункт — требование ТЗ или Definition of Done,
а не пожелание:

| Должно остаться | Откуда требование |
|---|---|
| Имя, категория, город, цена, объяснение в каждой карточке | ТЗ, требование 2 |
| Три исхода различимы явно | ТЗ, требование 6 |
| Сколько кандидатов есть и почему меньше трёх | ТЗ, требование 4 |
| Воронка отсева и список «кто не прошёл» — на главном экране, не в сноске | Спека, раздел 2.1 |
| Маркеры «синтетический профиль» и «цена ориентировочная» | ТЗ: «в демо должно быть видно, где настоящий профиль, а где ваш» |
| Тумблер «стереть имена» | DoD: объяснения не взаимозаменяемы |
| Порядок карточек задаёт бэк, интерфейс не пересортировывает | ТЗ, требование 5 (детерминизм) |
| Пустой результат объяснён словами | DoD |
| Блок стоимости проезда со всеми оговорками | Спека перелёта |

## 3. Найденный дефект, который чиним попутно

`app/globals.css` содержит `@media (prefers-color-scheme: dark)`, переключающий `--background`
на `#0a0a0a`, при том что весь текст в `app/page.tsx` прибит как `text-slate-900`.
**На машине с тёмной темой ОС заголовок, подписи и текст вне белых карточек становятся чёрным по чёрному.**
Если у жюри тёмная тема, демо разваливается на первом экране.

Решение: тёмная схема удаляется, светлая фиксируется. Тёмный режим в требованиях не значится,
а ломать демо способен.

## 4. Изменения

### 4.1 Токены и база — `app/globals.css`

Палитра из референса команды: `--ink #15171C`, `--muted #5B616E`, `--faint #8A909C`,
`--line #E4E6EB`, `--soft #F5F6F8`, `--accent #2450D6` (+ hover и soft), пары good / warn / bad.
Цвета сейчас разбросаны утилитами `slate-*` по разметке — сводятся к токенам.
Добавляется глобальный `:focus-visible`.

### 4.2 Шрифт — локально, без сети

Onest (вариативный, 400–700) в подмножествах cyrillic / latin / latin-ext лежит в
`public/fonts/onest-*.woff2`, 78 КБ суммарно. Подключается через `@font-face` с `unicode-range`
и `font-display: swap` в `globals.css`.

Почему не `next/font/google`: он скачивает файлы на этапе сборки. Локальные файлы убирают
сетевую зависимость из билда — это и страховка на площадке, и плюс к воспроизводимости,
которая в оценке весит 25 баллов. Импорты Geist из `app/layout.tsx` удаляются: сейчас они
грузятся впустую, потому что `body { font-family: Arial }` в CSS их перебивает.

### 4.3 Шапка и первый экран — `app/page.tsx`

Sticky-бар: слева «neIT.kz · подбор подрядчиков», справа мелким «66 профилей · окно 23.09 — 31.12.2026»
и тайминг последнего ответа с источником объяснений. Ниже h1 36px и лид.
Тайминг и источник сейчас показываются в углу формы — переезжают в шапку, не пропадают.

### 4.4 Исход — словами вместо кода

Сейчас `data.outcome` печатается сырым значением (`NO_ONE_PASSES`) в чёрном бейдже.
Вводится маппинг четырёх значений `Outcome` в заголовок и цвет:

| Значение | Заголовок | Тон |
|---|---|---|
| `MATCHED` | Подобрали | зелёный |
| `NO_CATEGORY_IN_CITY` | В этом городе таких нет | серый |
| `NO_FORMAT_IN_POOL` | Этот формат не берут | серый |
| `NO_ONE_PASSES` | Под ваши условия никто не подходит | янтарный |

Формулировки и само решение пришли из коммита `361c43c`, сделанного параллельно в соседней сессии:
мы независимо чинили одно и то же, вёрстка была переписана поверх, поэтому его содержательная
часть возвращена целиком. Оттуда же — технический код исхода мелкой подписью в шапке
«Как мы отбирали»: клиенту он не нужен, а в разделе про пайплайн он к месту и остаётся
на виду у жюри, которое проверяет различимость исходов.

Серый против янтарного разводит два разных случая: серый — «такого в каталоге нет вообще»,
янтарный — «есть, но не проходит». Плашка набирается обычным регистром, а не капителью:
с формулировкой «Под ваши условия никто не подходит» капитель превращалась в крик на полэкрана.

`data.message` выводится как есть, без правок. Неизвестное значение (если в `lib/types.ts`
появится пятое) отрисовывается нейтральным тоном и показывает сам код — экран не ломается.

### 4.5 Карточка

Сетка: имя 19/600 и мета серым слева, цена справа с `tabular-nums`.
**Объяснение набирается 16px** — сейчас `text-sm`, то есть мельче подписей формы, хотя это
главный продукт по критериям оценки.

Состав карточки не меняется: чипы фактов, `relaxation`, блок проезда со всеми оговорками
и снимком цен, «синтетический профиль», «цена ориентировочная», `details` с отличиями и score.
Три вида карточек различаются рамкой: обычная — сплошная, `soft` и `nearest` — пунктир с тёплым фоном.

### 4.6 Воронка

Из ряда серых чипов — в вертикальную шкалу с точками. Шаг, на котором выдача обнулилась,
помечается красным.

**Выводится поле `reason`**, которое `lib/filters.ts` уже кладёт в каждый `FunnelStep`
(«город «Алматы»», «цена до 1 500 000 ₸», «язык учтён как пожелание, а не как фильтр»),
а интерфейс сейчас выбрасывает. Правок на бэке не требует.

Список «кто не прошёл» — из абзаца в таблицу «кто | причина», на узком экране схлопывается в строки.

### 4.7 Форма и кнопки

Инпуты высотой 40px, радиус 10, focus-ring акцентом. Сценарии — pill-кнопки.
Основная кнопка синяя вместо чёрной. Состав полей и их порядок не меняются.

### 4.8 Метаданные — `app/layout.tsx`

`lang="en"` → `lang="ru"`. Title «Create Next App» → «Подбор подрядчиков под мероприятие · neIT.kz»,
description — по сути продукта.

## 5. Что не делаем

Не трогаем `lib/`, `data/`, `scripts/`, `tests/`. Не меняем тексты объяснений и сообщений.
Не меняем порядок карточек. Не прячем воронку, отсев и чипы за сворачивание.
Не добавляем бронирование, заявки и уведомления — ТЗ выносит их из области задачи.
Не добавляем анимаций тяжелее появления. Не вводим тёмную тему.

## 6. Проверка результата

1. `npm run test` и `npm run verify` проходят как до правок — слой представления их не касается, но прогон подтверждает, что ничего не задето.
2. Прогон сценариев `?s=S1`, `?s=S4`, `?s=S8`, `?s=S10`, `?s=S11`: три исхода видны словами, воронка показывает причины, блок проезда на месте.
3. Тумблер «стереть имена» работает, карточки остаются различимыми.
4. Один и тот же запрос дважды даёт тот же порядок карточек.
5. Страница проверяется при тёмной теме ОС — текст читается.
6. Скриншоты `docs/screen-S1.png`, `S3`, `S10`, `S11` переснимаются: README на них ссылается, а README и воспроизводимость — 25 баллов.
